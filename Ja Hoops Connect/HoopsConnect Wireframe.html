02 · UX Audit

What needs to change before we build.

Findings from your spec doc + the JBA workflow. Each card has a recommendation and where it lands in the prototype.

A1

Posts & "acknowledge or it didn't happen"

Your spec already includes ack-required posts — that's the right call. The issue is what happens after the deadline: the spec is silent on enforcement, escalation, and visibility.

  • +
    Ack tracker dashboard for admin. Per-post: who has, who hasn't, color-coded by overdue. Bulk "Send reminder" + "Call rep" SMS deeplink.
  • !
    Visible deadline countdown on each post for reps — not just "due date" text. Treats it like a task, not a notification.
  • ✓
    Acknowledgments are persistent (Firestore subcollection), not just push receipts.
A2

The "live stats" workflow is the riskiest part

Court-side stat entry is the highest-stakes interaction in the entire app — one tap on the wrong row inflates a player's PPG. Your spec lists it as a feature; it needs to be a dedicated mode.

  • +
    Lock the screen orientation, hide system chrome, and switch to a 3-column court-side layout — home roster · action pad · away roster. (See §04.)
  • +
    Two-tap rule: select player → select action. Never let a single tap mutate stats.
  • +
    Undo always available. Statisticians make mistakes. Last 5 actions log in the right rail.
  • !
    Auto-detect foul-out at 5 fouls — the player is force-benched, the statistician is prompted for a sub.
  • +
    Validation gates before "Submit": MIN ≤ 240/team, PTS = sum of made shots, no negatives. Block submission until clean.
A3

Stats lifecycle: who can edit, when?

This is missing from the spec entirely. Without it, you'll get the same mess JBA has now — competing versions of the same box score.

  • +
    States: not_started → in_progress → submitted → approved | rejected. Only Admin can move from submitted → approved.
  • +
    Stats are read-only once approved. Standings & leaderboards rebuild from approved games only — never from drafts.
  • +
    Reject path: Admin sends back to statistician with a note (subcollection comment). The statistician sees the rejection in their inbox.
A4

League scope is implicit; make it explicit

JBA runs multiple leagues simultaneously (NBL Premier, Women's Premier, Junior, etc.). Your spec mostly assumes "the league" — which breaks the second a Press user tries to filter, or an admin posts to one division.

  • +
    League scope bar at the top of every screen — like Slack's workspace switcher. Standings, schedule, posts, and stats all filter by it.
  • +
    Posts get an audience field: All / League / Specific teams. Admin can target.
A5

Press & Fan — separate experiences, not toggled flags

The spec lumps fans and press loosely. They want very different things.

  • ✓
    Fans want the public board, standings, schedule, leaderboards. No login required for read-only public content (Tier 1 in your data model).
  • +
    Press want a digital credential, auto-generated recaps, copy-button box scores, head-to-head comparators, and CSV export. Make this its own tab.
  • !
    Don't show admin-internal posts to public — separate visibility: public | internal on every post.
A6

Invite codes: who, what, expiry

Your code mentions invite codes but doesn't structure them. Roles + teams need to be baked into the code itself, not assigned post-hoc.

  • +
    Code shape: {TEAM}-{ROLE}-{HASH} e.g. TIT-REP-9X4. Single-use for reps/admins, multi-use for press/stats.
  • +
    Codes carry: role, team binding, max uses, expiry, generated-by. Stored in inviteCodes collection, validated by Cloud Function on signup.
  • +
    Super-admin can revoke a code mid-flight (mark inactive). Already-redeemed accounts unaffected.
A7

Things to remove from scope (for v1)

Your spec is ambitious. Here's what we'd cut to ship in 8-10 weeks instead of 20:

  • −
    Live game clock control from the app. Stats only — game clock is run by the table's existing equipment. (Optional Stats+Clock mode can come in v1.1.)
  • −
    Video / highlight clips. Storage cost + moderation overhead. Press can link to YouTube in posts.
  • −
    In-app messaging / DMs between users. Use the post system. WhatsApp wins for 1:1.
  • −
    Player-facing accounts. Players are data in v1, not users. Reps manage rosters. (Adds 6+ weeks if you let players log in.)
  • −
    Bracket builder for playoffs. v1 just shows the schedule. Bracket viz can be a v1.2 admin tool.

04 · Live Stats — Court-side Mode

The 3-column rule.

Open the live mode in the prototype () — it takes over the screen. Below: why it's structured this way.

L1

Why three columns?

Court-side, the statistician's eyes are on the floor — not the screen. The phone (or tablet) becomes a glance-and-tap surface.

  • ✓
    Left: home roster · 5 on court at top, bench below. Foul-count badges visible at a glance.
  • ✓
    Center: action pad — the only place stats are recorded. Every button is a single tap, never a sequence.
  • ✓
    Right: away roster + last-plays log (so the stat-taker can verify themselves without scrolling).
L2

Two-tap rule, and only two

Every action is exactly: tap player → tap action. No three-tap drill-downs, no modals, no confirmations. The undo button is the safety net.

  • +
    Selected player is highlighted with a dark border + scoreboard color. Esc / tapping the same player deselects.
  • +
    Action buttons are visibly disabled (greyed) until a player is selected. This is the single biggest source of "ghost stats" mistakes.
L3

Foul-out is automatic

At 5 fouls (FIBA rules), the player auto-benches and the statistician is prompted: "Pick a sub." The sub doesn't go into your selection state until you've actually chosen them.

L4

Auto-save semantics

Every action writes to Firestore in real-time. If the stat-taker's phone dies, they pick up where they left off on a different device. The game's events subcollection is append-only; deletes are tombstoned for audit.

L5

What's NOT in live mode (and why)

  • −
    Game clock. The table has a clock. Don't compete with it. (Stats+Clock optional toggle for venues that want it.)
  • −
    Shot chart. Cool, but adds 5 taps per shot. Defer to v1.2.
  • −
    Roster editing mid-game. If a player is missing, sub them in. Roster locks at game start.
05 · Data Model & Notifications

Firestore shape, and what fires what.

The minimum schema to make all six roles work. Cloud Functions are the only writers for derived data (standings, leaderboards, recaps).

D1

Firestore collections

leagues/{leagueId}                       — { name, season, divisions[], active }
  /teams/{teamId}                        — { name, short, color, record, divisionId }
    /players/{playerId}                  — { name, num, pos, height, active }
      /seasonStats/{season}              — { gp, pts, reb, ast, stl, blk, … }    [WRITTEN BY CF]
  /games/{gameId}                        — { homeTeamId, awayTeamId, date, venue, status: pending|final, statsStatus: not_started|in_progress|submitted|approved }
    /events                              — append-only stat events (player, action, qtr, time)
    /boxScore                            — derived snapshot                       [WRITTEN BY CF]
    /comments                            — admin↔statistician notes on rejection

users/{uid}                              — { name, email, role, teamId?, divisionIds[], pushTokens[] }
  /inbox/{itemId}                        — { type: ack|approve|reminder, refDoc, createdAt, dismissedAt? }

posts/{postId}                           — { authorUid, audience, leagueId?, teamId?, body, urgent, ackRequired, ackDeadline, visibility }
  /acks/{uid}                            — { ackedAt }                            [user-writeable]

inviteCodes/{code}                       — { role, teamId?, maxUses, usesCount, expiresAt, createdBy, active }

leaderboards/{leagueId}/{stat}           — top 50 cached                          [WRITTEN BY CF]
standings/{leagueId}                     — division → ordered teams               [WRITTEN BY CF]
D2

Cloud Functions (writers)

  • +
    onPostCreate — fan-out FCM, write inbox items, schedule SMS fallback for urgent.
  • +
    onAckWrite — if last ack lands, mark post resolved + notify admin.
  • +
    onStatsApproved — recompute team record + standings + season stats + leaderboards. Push to subscribed fans.
  • +
    generateRecap — on approval, draft press recap text from top performers.
  • +
    redeemInviteCode — atomic role binding + custom claims.
  • +
    onAckDeadline (scheduled) — every hour, surface overdue acks to admin inbox + send rep reminders.
